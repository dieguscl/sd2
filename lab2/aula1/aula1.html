SD2 · 2.º Trabalho · Gestão dos displays para o jogo Guitar Hero · Aula 1

1. Arquitetura a controlar + controlador (malha fechada). Saídas do controlador = comandos sobre a arquitetura; saídas da arquitetura (Start, Tempo) = entradas do controlador. Ligações pelo nome do sinal; /n = barramento de n bits.

2. Fluxograma do controlo

Algoritmo (secção 2.1 do enunciado)

  • S0 (só com Reset): limpa a memória e o LED Beat, carrega a semente no LFSR, inicializa o temporizador variável.
  • S1: Ready aceso; o LFSR avança livremente; espera que se carregue Start.
  • S2: Ready continua aceso; espera que se largue Start.
  • S3 (um ciclo): Ready apaga-se; desloca a memória carregando 2 bits do LFSR em Pos0; troca o LED Beat; começa a contagem.
  • S4: Waiting aceso enquanto o temporizador conta (Tempo = 1).
  • S5 (opcional, um ciclo): acelera ligeiramente o temporizador e repete a partir de S3.

Ready e Waiting não precisam de latch SR: estão ativas em todos os estados entre acender e apagar (secção 2.4). EnLFSR está ativa em todos os estados (o LFSR avança sempre). Cada passo do jogo dura Periodo + 3 ciclos de relógio.

Variáveis e estados lidos no fluxograma

  • Entradas (variáveis testadas nas decisões): Start (tecla já sincronizada) e Tempo (temporizador). O Reset não é uma decisão: atua de forma assíncrona e põe a máquina em S0.
  • Saídas (variáveis ativas nos estados, todas de Moore): ClrMem, InitLFSR, EnLFSR, ShiftMem, RstTemp, StartTemp, Faster, TglBeat, Ready, Waiting.
  • Estados / blocos: 6 (S0…S5). Cada bloco tem um só estado, no máximo uma decisão, não tem ciclos no seu interior e tem um único estado seguinte para cada combinação das entradas: o fluxograma é válido.

Passo 2 · Eliminar estados redundantes

Inspeção visual: duas linhas com as mesmas saídas e o mesmo estado seguinte em todas as colunas seriam redundantes. Não há nenhuma: S1 e S2 têm as mesmas saídas mas estados seguintes diferentes.

P1 = (S0)(S1 S2)(S3)(S4)(S5)separados pelas saídas
P2 = (S0)(S1)(S2)(S3)(S4)(S5)Start Tempo = 00: S1 → S1 ∈ (S1 S2), S2 → S3 ∈ (S3)
P3 = P2fim: 6 classes = 6 estados

Conclusão: nenhum estado é redundante.

Passo 3 · Agregar estados compatíveis (fusão)

A tabela está completamente especificada (não há estados seguintes nem saídas indiferentes "–"), por isso dois estados só são compatíveis se forem equivalentes. O único par com saídas iguais, (S1, S2), já foi separado no passo 2: o grafo de fusão não tem arestas e não há estados a agregar.

Passo 4 · Tabela de estados reduzida

É a própria tabela primitiva: 6 estados (S0…S5), nenhum eliminado nem agregado. Todos são precisos: S1 e S2 esperam que se carregue e depois que se largue Start; S3 (deslocar) e S5 (acelerar) duram um só ciclo de relógio; S4 espera pelo fim do tempo; S0 inicializa a arquitetura.

4. Projeto do controlador · passos 5 a 9: codificação, transições e equações

Passo 5 · Codificação dos estados livre de corridas críticas

O enunciado impõe a realização direta: um flip-flop por estado (codificação one-hot), 6 FF em vez dos 3 de uma codificação mínima. Cada FF corresponde a um estado do fluxograma.

EstadoQ5 Q4 Q3 Q2 Q1 Q0Flip-flopPrimitiva / inicialização
S00  0  0  0  0  1FF_S0FDPE: PRE = Reset, INIT = 1
S10  0  0  0  1  0FF_S1FDCE: CLR = Reset, INIT = 0
S20  0  0  1  0  0FF_S2FDCE: CLR = Reset, INIT = 0
S30  0  1  0  0  0FF_S3FDCE: CLR = Reset, INIT = 0
S40  1  0  0  0  0FF_S4FDCE: CLR = Reset, INIT = 0
S51  0  0  0  0  0FF_S5FDCE: CLR = Reset, INIT = 0

Corridas: em cada transição mudam 2 FF (o do estado que sai vai a 0 e o do que entra vai a 1). Numa máquina assíncrona isso seria uma corrida; aqui todos os FF mudam no mesmo flanco do relógio e as entradas D só voltam a ser lidas no flanco seguinte, já estáveis (folga de 5,1 ns medida pelo Vivado): não há corridas críticas. O único acontecimento assíncrono é a libertação do Reset: se FF_S0 saísse do PRE antes de FF_S1 sair do CLR, a máquina ficava em 000000 sem sair de lá (corrida crítica). Fica resolvido com o SincronizadorReset, que ativa o Reset de imediato mas só o liberta num flanco do relógio.

Saídas de Moore: só mudam logo a seguir ao flanco do relógio. A única saída que atua de forma assíncrona (ClrMem, no CLR dos registos) é tirada diretamente de um flip-flop, por isso nunca tem picos; as que passam por uma OR só vão para entradas síncronas ou LEDs.

Passo 8 · Equações de excitação

Cada DSk é a soma dos termos das linhas da tabela de transições com Dk = 1. Em one-hot Qj = 1 identifica sozinho o estado, por isso cada termo é só Sj·condição (não há mapas de Karnaugh a minimizar).

DS0 = 0nenhum percurso entra em S0 (só a tecla Reset, pelo PRE)
DS1 = S0 + S1·/Startvem de S0, ou fica em S1
DS2 = S1·Start + S2·Startvem de S1, ou fica em S2
DS3 = S2·/Start + S5vem de S2 ou de S5
DS4 = S3 + S4·Tempovem de S3, ou fica em S4
DS5 = S4·/Tempovem de S4 (sem S5: DS3 = S2·/Start + S4·/Tempo)

Sem acidentes: um pico na lógica do D não tem efeito, porque o FF só lê D no flanco, depois de estabilizar. Start chega já sincronizada e Tempo é síncrono, por isso nenhuma entrada assíncrona chega a estas portas.

Passo 9 · Equações de saída

Lidas nas colunas das saídas da tabela primitiva (soma dos estados com 1):

EnLFSR = S0 + S1 + S2 + S3 + S4 + S5Waiting = S4

Ensaio na Basys3

  • Implementação: 6 FF do controlador (1 FDPE + 5 FDCE), restrições de tempo cumpridas (folga 5,1 ns).
  • LD10…LD15 mostram o FF ativo: depois de BTNU (Reset) acende LD11 (S1) e LD0 (Ready).
  • Carregar BTNC: LD12 (S2). Largar: Ready apaga, LD14 (S4) quase sempre aceso, LD1 (Beat) troca a cada passo.
  • As cordas entram pelo display da esquerda e avançam; a sequência acelera de 0,5 s até 0,2 s por passo.
